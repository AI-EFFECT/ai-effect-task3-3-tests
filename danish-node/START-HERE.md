# Danish node: start here

## Prerequisites

- Docker Desktop (or Docker Engine) with Compose v2, running.
- Python 3.9 or newer. The suite uses only the Python standard library; no `pip install` is needed.
- PowerShell: Windows PowerShell 5.1 or PowerShell 7 (`pwsh`). It is used to read `Test-Settings.psd1` exactly as the other node suites do.
- Git.
- Roughly 5 GB free disk space for the images and the Ollama model.

## Local layout

Clone the source and this suite side by side. Windows example:

```text
C:\T33\ai-effect-wp3
C:\T33\ai-effect-task3-3-tests
C:\ae33dk-evidence
```

Mac or Linux example:

```text
~/T33/ai-effect-wp3
~/T33/ai-effect-task3-3-tests
~/T33/ae33dk-evidence
```

## Prepare the frozen source

```bash
git clone https://github.com/AI-EFFECT/ai-effect-wp3.git
cd ai-effect-wp3
git checkout e8914565e966a2d78879c314f980574769d31b87
```

Do not edit the source tree. The export generated by script 01 is written to `use-cases/denmark-node/export/`, which the source repository ignores, so the tree stays clean.

## Settings

Copy `Test-Settings.psd1.example` to `Test-Settings.psd1` in this folder and adapt only the local paths. Keep `ExpectedCommit` and the service URLs unless the runbook changes.

## Keys

Create temporary random keys in the terminal you will use for every script, without displaying them. They only protect your local stack. Never commit or print them.

Windows PowerShell (same method as the other node runbooks):

```powershell
function New-TestSecret {
    $bytes = New-Object byte[] 32
    $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
    $rng.GetBytes($bytes)
    $rng.Dispose()
    -join ($bytes | ForEach-Object { $_.ToString('x2') })
}
$env:ORCHESTRATOR_API_KEY = New-TestSecret
$env:SERVICE_API_KEY = New-TestSecret
```

Mac or Linux:

```bash
export ORCHESTRATOR_API_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")
export SERVICE_API_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")
```

`ORCHESTRATOR_API_KEY` must be set before script 01 starts the orchestrator, otherwise the orchestrator runs without authentication and script 02 fails. If you open a new terminal, stop the stacks and start again with new keys.

## Run order

Run from this folder. Use `python` on Windows and `python3` on Mac or Linux.

```text
python 00_preflight.py
python 01_start_services.py
python 02_test_authentication.py
python 10_test_workflow.py
python 11_validate_outputs.py
python 12_test_prompt_workflow.py
python 20_test_invalid_input.py
python 23_test_repeatability.py
python 24_test_restart_and_rerun.py
python 25_test_bounded_concurrency.py
python 99_collect_closeout.py
```

The first run of script 01 builds the images and downloads the Ollama model, which can take several minutes. Use `--skip-ollama` to skip the model; script 12 is then reported as blocked.

## Reading results

Every script writes a timestamped folder under `EvidenceRoot` and ends with one `RESULT:` line. Read that line and the structured summary, not the process exit code. Preserve evidence from failed and blocked runs as well as passes.

## Stopping

Stop the stacks with `docker compose down` in `use-cases/denmark-node` and in `orchestrator`. Do not use `down -v` unless you intend to delete the shared data volume and the downloaded Ollama model.

Then remove the keys from the terminal:

```powershell
Remove-Item Env:\ORCHESTRATOR_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:\SERVICE_API_KEY -ErrorAction SilentlyContinue
```

```bash
unset ORCHESTRATOR_API_KEY SERVICE_API_KEY
```
